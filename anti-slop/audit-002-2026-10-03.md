# antislop audit-002 — Notifications page

**Scope:**  
[`apps/frontend/src/features/notifications/notifications-page.tsx`](../apps/frontend/src/features/notifications/notifications-page.tsx)  
(+ related: `notification-priority-badge.tsx`, compose/receipts dialogs, page route via `StreamedDomainChrome`)  
**Out of scope for this audit file:** header bell (`notifications-bell.tsx`) except as a quality contrast.  
**Mode:** AFTER (audit only; no code changes until numbers approved)  
**Direction:** `DESIGN.md` — zarva-gold, calm atelier, gold accent on key numbers; dial ENERGY 2 / RHYTHM 2 / MOTION 2  
**Design read:** Inbox / sent alerts for shop owners and floor managers; should feel like a live atelier feed, not a generic CRUD table.

---

## Findings

### 1 — HIGH (R-20 / Part 3 liveliness / C-1 / Sterile Default)

**Where:** Whole page body: tabs → `FilterSearch` → `DataTable`  
**Rule:** R-20; Part 3 focal point + identity motif; C-1  
**Why:** The full page is a sterile DomainList clone. Unread items have no gold unread mark, no stronger title weight, no feed rhythm. The header bell already shows unread dots + stacked feed rows; the “View all” page is visually poorer than the dropdown. Swap the product name and it still feels like any admin table.  
**Fix:** Rebuild as a notification feed (list rows with unread accent, priority, time, expandable body). Keep glass table wrapper only if it still reads as an atelier inbox. Put unread count as the sole gold focal number (see #2). Match or beat the bell’s hierarchy.

### 2 — HIGH (Part 3 focal point / DESIGN.md accent / R-31)

**Where:** Footer `total` + muted `· Unread N`; unused i18n `kpi.unread` / `kpi.today` / `kpi.sent`  
**Rule:** Part 3 levers; DESIGN.md “gold on key numbers”; R-31  
**Why:** The only number that matters (unread) is buried in muted footer text. No KPI rail / header chip. Accent discipline fails: gold is not on the key moment.  
**Fix:** Surface unread as a compact gold `zarva-num` (header action strip or single nested metric, reusing `KpiGrid`/`MetricCardShell` anatomy if a metric tile is justified). Do not invent a 3-tile fake KPI collage.

### 3 — HIGH (R-26)

**Where:** Footer Prev / Next `Button` with `disabled` always (`notifications-page.tsx` ~298–304, ~383–388)  
**Rule:** R-26 Hard Gate  
**Why:** Interactive-looking controls that never paginate. Dead furniture.  
**Fix:** Wire real pagination from the API, or remove the buttons entirely until pagination exists.

### 4 — HIGH (R-02)

**Where:** Inbox author fallback `author: item.createdByName ?? '—'`  
**Rule:** R-02 Hard Gate  
**Why:** Em dash character in UI copy path.  
**Fix:** Use a locale string (e.g. `t('unknownAuthor')` / en-dash-free placeholder like `—` replaced with `-` or an i18n “Unknown”) with no em dash.

### 5 — HIGH (R-03 / antislop-layoutmobile)

**Where:** `DataTable` `min-w-[640px]` + 4 inbox columns (Alert / From / Time / Status)  
**Rule:** R-03  
**Why:** On phone the inbox only horizontal-scrolls a spreadsheet. Notifications are naturally a vertical feed; the mobile state is “desktop squeezed,” not a designed reflow.  
**Fix:** Mobile: stacked feed cards/rows (title + meta + status); desktop: denser list or table. No reliance on sideways scroll as the mobile design.

### 6 — MEDIUM (C-2 / R-26 partial)

**Where:** Inbox row `onClick` only calls `markRead`; body is `line-clamp-1`; no detail / expand  
**Rule:** C-2; R-26 spirit  
**Why:** Clicking an alert marks it read but never shows the full message. Users open the page to read; the UI refuses.  
**Fix:** Expand-in-place, side panel, or dialog with full title + body + actions (terminate session stays there). Mark-read on open/expand remains fine.

### 7 — MEDIUM (C-2 / product completeness)

**Where:** Page has no “Mark all read”; only the bell dropdown does  
**Rule:** C-2; R-26 (missing primary action on the destination page)  
**Why:** The full inbox is where bulk clear belongs; sending people to “View all” then omitting the action is incomplete.  
**Fix:** Add `markAllRead` beside compose / unread chip when `unread.count > 0`.

### 8 — MEDIUM (R-05 / RHYTHM dial mismatch)

**Where:** Inbox and Sent use the same table shell; compose is a lone `justify-end` button in `chrome="body"`  
**Rule:** R-05; DESIGN.md RHYTHM 2  
**Why:** Declared rhythm is “shell vs content vs tables differ”; this surface is one uniform filter+table block with a floating CTA.  
**Fix:** Distinct chrome: toolbar (search + tabs + actions) vs feed body; sent receipts as a secondary pattern, not a carbon-copy column set without hierarchy.

### 9 — MEDIUM (R-09 / Part 1 colored left stripe / R-31)

**Where:** `priorityRowClass` inset stripe + always-visible `NotificationPriorityBadge` on every row  
**Rule:** R-09 Purpose-Gate; Part 1 “Colored Left Stripe”; R-31  
**Why:** Priority treatment is functional, but NORMAL/LOW badges on every row + stripe language without unread hierarchy reads as default badge furniture. Bell only shows HIGH/CRITICAL badges.  
**Fix:** Align with bell: badge (and stripe) only for HIGH/CRITICAL; unread uses gold dot/weight. Keep CRITICAL/HIGH unmistakable.

### 10 — LOW (R-27 / resilience polish)

**Where:** Loading = `DataTableSkeleton`; empty/error exist  
**Rule:** R-27  
**Why:** States exist (PASS floor), but skeleton is spreadsheet columns while a feed redesign (#1/#5) needs matching skeleton anatomy so Suspense → live does not morph layout.  
**Fix:** After feed redesign, ship a feed-shaped skeleton (and keep empty/error copy).

### 11 — LOW (R-35 / verify)

**Where:** Deliverable process  
**Rule:** R-35  
**Why:** This audit did not run the app or click-through controls; findings are from code + DESIGN.md contrast with the bell.  
**Fix:** After approved fixes, run typecheck/lint and a recorded click-through (inbox expand, mark all, compose, receipts, mobile width).

- No fake stats / testimonials on this page (R-17 / R-18).  
- Direction exists in `DESIGN.md` (R-37).  
- Bell dropdown is a better unread-feed reference to elevate toward, not tear down.
