# antislop audit-001 — ReportHero («جمع اصلی»)

**Scope:** [`apps/frontend/src/features/reports/report-hero.tsx`](../apps/frontend/src/features/reports/report-hero.tsx) + matching skeleton in `report-skeletons.tsx`  
**Mode:** AFTER (audit only; no code changes until numbers approved)  
**Direction:** `DESIGN.md` — zarva-gold, calm atelier, gold accent on key numbers  
**Design read:** Report summary tile for shop owners; dial ENERGY 2 / RHYTHM 2 / MOTION 1

---

## Findings

### 1 — HIGH (Liveliness / C-1 / Part 3 focal point)

**Where:** `ReportHero` body  
**Rule:** Focal point + intentionality (Part 3 levers; C-1)  
**Why:** Headline total uses the same `text-[1.65rem]` as KPI footer values, so the summary column has no clear hero number. Against DESIGN.md (“gold accent on key numbers”) the box reads sterile, not precious.  
**Fix:** Make the total the sole focal point: larger `zarva-num` (display scale), gold primary, more vertical breathing room; keep period + hint subordinate.

### 2 — MEDIUM (R-14 / surfaces metric anatomy)

**Where:** Body stack (value → chip → hint floating in empty space)  
**Rule:** R-14 Purpose-Gate; Metric & content boxes in `surfaces.mdc`  
**Why:** Value sits in open body padding like a short AI panel, not like a metric surface. No nested footer rail; hierarchy between total and meta is weak.  
**Fix:** Keep `DashboardPanel` shell (law). Put the total in a nested `border-t border-primary/12 bg-nested/70` rail (same language as `KpiGrid`); period chip beside or under the total in that rail; hint stays in the soft upper body.

### 3 — MEDIUM (R-09 / R-31)

**Where:** Period `<span className="rounded-md …">`  
**Rule:** R-09 Purpose-Gate; R-31  
**Why:** Chip is fine as a functional period label, but stacked under a mid-size number it looks like default badge furniture. Purpose not visually clear vs KPI chips.  
**Fix:** Keep chip only as period meta inside the nested rail (tabular, muted). Do not add glow/pill/dot. Optional: drop “Period ·” redundancy if the panel title already implies summary — prefer shorter `{period}` only if i18n allows.

### 4 — LOW (R-27 / empty resilience)

**Where:** `total || '—'` and empty chart sibling  
**Rule:** R-27  
**Why:** Empty state exists (`—`) but the tall empty body still looks unfinished when total is missing; skeleton already shows a stronger structure than the loaded empty state.  
**Fix:** Same nested-rail layout when value is `—` so loading → empty → data do not change anatomy.

### 5 — LOW (skeleton parity)

**Where:** `report-skeletons.tsx` summary panel  
**Rule:** progressive-loading + surfaces skeleton rules  
**Why:** Skeleton shimmers float like the live body; if finding 2 lands, skeleton must mirror the nested rail or loading→loaded will jump.  
**Fix:** Update summary skeleton to header + body hint shimmer + nested rail value/chip shimmers.

### 6 — PASS notes (no change needed unless asked)

- R-02: `periodBadge` uses middle dot `·`, not em dash `—`.  
- R-10: single glass card via `DashboardPanel`; dose OK.  
- R-04: kind icon via accent square; relevant.  
- Stays inside surfaces law (`DashboardPanel`, not a custom glass invention).
